# 超声与相控阵设备接入及标定准备清单

## 1. 文档目的

本文用于指导常规超声（UT）和相控阵超声（PAUT）设备接入当前罐体多模态检测系统，
同时作为向设备厂家、探头厂家、机器人团队和标定团队收集资料的统一清单。

本文覆盖：

- 接入前必须明确的设备、协议、SDK 和数据语义。
- 设备需要提供的数据流、时间、触发、控制和诊断接口。
- 常规超声如何适配当前 `UltrasoundFrame` 消息。
- 相控阵数据为什么需要专用接口，以及专用接口应包含的内容。
- 时间、设备、探头/楔块、声学、空间外参和编码器标定所需资料。
- 单设备、多设备和系统级验收要求。

本文不把“Topic 能够发布”视为接入完成。生产接入至少需要同时满足：数据语义明确、
时间可追溯、空间关系有效、检测配置可追溯、异常可诊断、原始数据可录制和回放。

## 2. 当前系统边界

当前系统是基于 ROS 2 的多模态数据闭环，已具备：

1. 原始传感器数据采集。
2. 以超声或涡流帧为锚点的时间戳关联。
3. 相机、点云、IMU 和机器人位姿的时间匹配。
4. MCAP 分卷录制、校验和回放。
5. 有界缓存、迟到/乱序统计和诊断输出。

当前“闭环”是“采集—时间关联—存储—校验—回放”的数据闭环，不是检测结果自动控制
机器人降速、暂停或复扫的控制闭环。

现有超声标准 Topic 和消息为：

```text
/inspection/ultrasound/raw
inspection_interfaces/msg/UltrasoundFrame
```

现有消息字段如下：

| 字段 | 当前语义 |
|---|---|
| `header.stamp` | 超声帧采样/触发时间，必须转换到统一 ROS 时间域 |
| `header.frame_id` | 探头坐标系，建议为 `ultrasound_probe_link` |
| `sequence` | 设备帧序号，正常运行期间单调递增 |
| `sensor_id` | 采集设备和探头组合的稳定标识 |
| `calibration_id` | 本帧使用的标定版本 |
| `channel_count` | 通道数 |
| `sample_count` | 每通道采样点数 |
| `sampling_rate_hz` | ADC 采样率，单位 Hz |
| `gain_db` | 接收增益，单位 dB |
| `sound_velocity_m_s` | 当前采用的工件声速，单位 m/s |
| `coupling_score` | 可解释的耦合质量分数 |
| `contact_force_n` | 探头接触力，单位 N |
| `sample_encoding` | 原始样本编码和缩放方式说明 |
| `samples` | `int16[]`，按 channel-major 排列 |

数组索引约定：

```text
samples[channel * sample_count + sample]
```

探头接触状态使用：

```text
/inspection/probe_state
inspection_interfaces/msg/ProbeState
```

包含接触力、lift-off、温度、耦合分数、接触有效状态和质量标志。

### 2.1 当前接口对相控阵的限制

现有 `UltrasoundFrame` 适合常规单通道/多通道 A 扫，或者已经完成波束形成的少量 A 扫。
它不能无歧义表达以下相控阵信息：

- `tx × rx × sample` 的 FMC 数据维度。
- 阵元几何、发射/接收孔径和坏阵元状态。
- 聚焦法则、延迟表、角度、焦深和加权系数。
- 一帧中每个 shot 的独立采样时间。
- 一轮法则扫描是否完整，以及具体丢失了哪个 shot。

因此：

- 常规超声可直接适配现有 `UltrasoundFrame`。
- 波束形成后的 PAUT 数据可在联调阶段临时映射到 `UltrasoundFrame`。
- FMC、PWI 或需要保留完整聚焦法则语义的数据必须使用新的相控阵专用消息。

## 3. 接入前需要设备厂家提供的资料

### 3.1 设备和软件基本资料

- [ ] 设备厂家、型号、硬件版本和序列号。
- [ ] 采集卡型号和序列号。
- [ ] 探头、楔块和转接板型号及序列号。
- [ ] 固件版本及固件升级/回退方式。
- [ ] SDK、驱动和上位机软件版本对应关系。
- [ ] Linux C/C++ SDK 或完整公开通信协议。
- [ ] SDK 支持的操作系统和架构，优先要求 Linux x86_64 和 ARM64。
- [ ] 线程模型、回调模型、内存所有权和缓冲区生命周期说明。
- [ ] 官方示例程序、编译说明和最小采集示例。
- [ ] 错误码、告警码和状态位说明。
- [ ] 允许同时打开的设备数量及设备枚举/唯一标识方法。

若厂商只提供 Windows GUI、不提供原始数据接口或稳定 SDK，则不能完成当前系统的生产接入。

### 3.2 物理和通信接口

- [ ] USB、GigE、10GigE、PCIe、串口或其他物理接口类型。
- [ ] 实际持续带宽、峰值带宽和推荐主机配置。
- [ ] 网络设备的 IP、端口、MTU、组播/单播和丢包重传机制。
- [ ] 数据包长度、包头、帧头、字节序、校验和/CRC。
- [ ] 分包、组帧、超时和不完整帧判定规则。
- [ ] 数据包序号、帧序号和 shot 序号的回绕规则。
- [ ] 设备断电、重启和重连后序列号的行为。

### 3.3 原始数据接口

数据回调或协议至少必须提供：

- [ ] 设备采样时间戳。
- [ ] 帧序号和触发序号。
- [ ] 原始波形数据指针/字节数组及有效长度。
- [ ] 通道、法则、shot、阵元和采样点的维度。
- [ ] 数据排列顺序。
- [ ] 数据类型，例如有符号/无符号 16 位、24 位或浮点数。
- [ ] 字节序、零点、比例系数、物理单位和饱和值。
- [ ] 当前配置版本或配置哈希。
- [ ] 本帧完整/不完整、饱和、脱耦和硬件错误标志。
- [ ] 设备累计采集、丢包、丢帧和缓冲区溢出计数。

不得只提供 S 扫截图、渲染图、厚度结果或缺陷列表。为了保证算法可复现和后续重处理，
必须能够获取原始 A 扫、波束数据或约定的 FMC/PWI 原始数据。

### 3.4 配置和控制接口

SDK 或协议至少需要提供：

- [ ] 设备枚举、连接、断开和重连。
- [ ] 加载配置、查询当前配置和原子应用配置。
- [ ] 开始采集、停止采集、触发准备和取消准备。
- [ ] 软件触发；如果设备支持，还需提供硬件触发配置。
- [ ] 设置并读取采样率、采样点数、PRF、增益和采样延迟。
- [ ] 设置并读取滤波、平均、整流、闸门、TCG/DAC 等处理参数。
- [ ] 查询温度、电压、同步状态、丢包、过载和缓冲区状态。
- [ ] 每个控制命令返回命令 ID、执行结果、实际生效时间和错误码。
- [ ] 配置修改后返回新的 `config_revision` 或配置哈希。

配置不能只写不读。适配器必须能够查询设备实际生效的配置，避免“上位机显示值”和设备
实际采集参数不一致。

### 3.5 离线样例和复现资料

- [ ] 不少于三组已知目标的原始采集数据。
- [ ] 与样例数据对应的完整设备配置。
- [ ] 正常、无耦合、饱和、丢帧和断连等异常样例。
- [ ] 厂商离线解析或回放工具。
- [ ] 样例数据预期结果和人工判读说明。
- [ ] SDK/协议版本及数据格式版本说明。

## 4. 时间戳和触发接口要求

### 4.1 最低要求

设备必须在数据产生端提供采样时间戳。不得把 ROS 适配器回调时间或主机收包完成时间冒充
硬件采样时间。

厂家必须明确：

- [ ] 时间戳位宽和单位，例如 64 位纳秒或微秒。
- [ ] 时间戳使用的时钟源和时间原点。
- [ ] 时间戳表示发射时刻、第一采样点、最后采样点还是完整帧结束时刻。
- [ ] 时钟分辨率、标称精度和长期漂移。
- [ ] 时钟回绕、跳变、设备复位和断电后的行为。
- [ ] 一帧包含多个 shot 时，各 shot 相对于帧时间戳的偏移。

### 4.2 推荐能力

按优先级推荐：

1. IEEE 1588 PTP 硬件时间戳和同步锁定状态。
2. PPS 输入/输出及对应时间事件。
3. Trigger In/Out，能够与机器人编码器或其他传感器共享触发事件。
4. 设备时间与主机时间的周期映射接口。

无论采用哪种方式，都必须记录：

- 设备时间。
- 转换后的 ROS 时间。
- 主机接收时间。
- 当前估计的 offset、drift 和 jitter。
- PTP/PPS/触发同步是否锁定。

### 4.3 时间精度的确定方式

时间误差要求应从空间定位误差反推：

```text
允许时间误差 = 允许的沿扫描方向位置误差 / 最大扫描速度
```

在冻结接口前，项目方需要明确最大扫描速度和允许的空间误差。设备时间精度、机器人位姿
时间精度、通信抖动和插值误差的总和必须小于该时间预算。

## 5. 常规超声接入要求

### 5.1 推荐的一帧定义

一条 `UltrasoundFrame` 推荐对应：

- 单通道设备：一次完整 A 扫。
- 多通道设备：同一个触发事件下的完整多通道 A 扫集合。

字段映射要求：

| 项目 | 映射规则 |
|---|---|
| 时间 | `header.stamp` 使用该次触发/采样的设备时间并转换到 ROS 时间域 |
| 坐标系 | `header.frame_id=ultrasound_probe_link` 或经批准的唯一探头坐标系 |
| 序列号 | `sequence` 使用设备帧序号；如由适配器生成，需要明确重启规则 |
| 标识 | `sensor_id` 能唯一指向设备、采集卡和探头组合 |
| 标定 | `calibration_id` 指向机器可读取的标定记录 |
| 布局 | `samples` 按 channel-major 排列 |
| 编码 | 优先保留原始 ADC `int16`；非 int16 数据需给出无损或可审计转换规则 |
| 质量 | 耦合质量和接触力必须来自明确算法/传感器；未知时标记无效 |

### 5.2 现有消息尚未包含的配置

以下参数不能只存在于厂家 GUI 中，应通过配置 Topic、任务清单或带版本的 YAML/JSON 留档：

- 脉冲电压、脉冲宽度和中心频率。
- PRF、采样延迟/时间零点和采样范围。
- 高通、低通、带通、整流和平均参数。
- 闸门起点、宽度、阈值及闸门用途。
- TCG/DAC 曲线。
- 探头、楔块、耦合剂和工件材料信息。
- 原始 ADC 到物理量的缩放关系。
- 厂商内部处理算法和版本。

建议增加带 `config_revision` 和配置哈希的瞬态本地配置 Topic，并在每个 MCAP 中至少记录
一次完整配置。

## 6. 相控阵接入要求

### 6.1 需要明确的采集模式

厂家必须说明实际输出属于：

- 波束形成后的 PAUT A 扫。
- 扇形扫查/线性扫查对应的法则集合。
- FMC：`tx × rx × sample`。
- PWI：`plane_wave × rx × sample`。
- 其他自定义模式。

不同模式不得共用一个未定义的数据数组。数据包和 ROS 消息必须明确维度及排列顺序。

### 6.2 相控阵原始帧必须包含的内容

建议新增：

```text
/inspection/phased_array/raw
inspection_interfaces/msg/PhasedArrayFrame
```

专用消息至少需要表达：

| 类别 | 必需字段/语义 |
|---|---|
| 通用头 | ROS 时间、探头坐标系、帧序号、触发 ID、设备 ID、标定 ID、配置版本 |
| 采集模式 | PAUT/FMC/PWI/其他模式 |
| 维度 | 元素数、发射数、接收数、法则数、波束数、每通道采样点数 |
| 时间 | 帧起始时间及每个 shot 的时间偏移 |
| 布局 | `law × sample`、`tx × rx × sample` 等明确的数组布局 |
| 数据编码 | 类型、字节序、比例系数、零点、单位和压缩方式 |
| 完整性 | shot 数量、丢失 shot 位图、不完整帧标志、CRC/校验状态 |
| 质量 | 饱和、坏阵元、耦合状态、设备错误和质量标志 |

高带宽数据如需分块，还必须包含：

- `frame_sequence`。
- `chunk_index` 和 `chunk_count`。
- 本块起始元素/法则/shot 索引。
- 本块有效字节数和校验值。
- 超时后丢弃不完整帧的确定性规则。

### 6.3 相控阵配置接口必须包含的内容

建议单独记录带版本的配置，而不是在每个原始大帧中重复全部配置：

```text
/inspection/phased_array/config
```

配置至少包含：

- 探头型号、序列号、阵元数量、阵元间距和阵元空间坐标。
- 阵元中心频率、带宽、阵元尺寸和坏阵元列表。
- 楔块型号、序列号、几何尺寸、角度和第一阵元参考位置。
- 楔块纵波/横波声速、楔块延迟和温度修正方式。
- 工件材料、采用的纵波/横波声速和温度。
- 发射/接收阵元掩码。
- 各聚焦法则的角度、焦深、延迟表和 apodization。
- 采样率、采样点数、时间零点、PRF、增益和滤波。
- 闸门、TCG/DAC、平均和整流参数。
- 配置生成软件、算法版本、配置版本和内容哈希。

### 6.4 联调阶段的临时兼容方式

如果厂家只输出波束形成后的 `law × sample` 数据，可在联调阶段临时映射为：

```text
channel_count = law_count
sample_count  = 每条法则的采样点数
samples       = law-major/channel-major
```

此方式必须满足：

- 一条消息对应一个完整法则周期。
- 所有法则采样点数一致。
- 法则顺序固定并由外部配置文件说明。
- `header.stamp` 明确是第一个 shot 还是法则周期中心时刻。
- 法则周期内的时间跨度满足当前定位精度要求。

这种映射不适合 FMC/PWI，也不能表示每个 shot 的独立时间，因此只能用于数据链路联调，
不能替代相控阵生产接口。

### 6.5 原始数据与派生结果分离

建议保持以下边界：

- `/inspection/phased_array/raw`：厂家原始或约定的可重建数据。
- `/inspection/phased_array/config`：带版本的完整配置。
- `/derived/inspection/phased_array/...`：S 扫图、厚度、缺陷候选、置信度等派生结果。

不得用渲染截图替代原始波形，也不得将派生缺陷结果写回原始 Topic。

## 7. 标定需要提供的资料和实物

标定不是单一的外参标定，应分别完成设备/通道、探头/楔块、材料声学、空间外参、时间和
位置编码器标定。所有标定结果必须有唯一 `calibration_id`。

### 7.1 设备和通道标定

需要厂家或标定团队提供：

- [ ] ADC 零点、满量程、分辨率和原始码值到电压/幅值的转换关系。
- [ ] 各通道增益线性、幅值一致性和通道间补偿值。
- [ ] 各通道固定延迟和通道间时间偏差。
- [ ] 系统噪声底、动态范围、饱和阈值和死区。
- [ ] 采样率准确度和时基准确度。
- [ ] TCG/DAC、滤波和平均处理对幅值/相位的影响。
- [ ] 相控阵坏阵元检测结果和坏阵元列表。
- [ ] 设备温漂测试或温度补偿方法。
- [ ] 标定使用的设备配置和固件/SDK版本。

### 7.2 探头和楔块标定

常规超声需要：

- [ ] 探头型号、序列号、中心频率、带宽和晶片尺寸。
- [ ] 声束轴定义、声学原点和探头机械参考面。
- [ ] 探头零点/延迟和灵敏度。
- [ ] 楔块型号、序列号、几何尺寸、角度、材料和声速。
- [ ] 楔块延迟、入射点和磨损补偿。

相控阵还需要：

- [ ] 阵元数量、pitch、gap、elevation 和阵元坐标。
- [ ] 第一阵元方向和阵元编号顺序。
- [ ] 阵元幅值与延迟一致性。
- [ ] 各聚焦法则的实际声束角度、出射点和焦点验证结果。
- [ ] 楔块与阵列的装配偏差及第一阵元相对机械基准的位置。
- [ ] 坏阵元对法则和成像的处理规则。

### 7.3 工件和声学标定

- [ ] 工件材料牌号和状态。
- [ ] 标定温度和实际检测温度范围。
- [ ] 纵波、横波或表面波声速及其确定方法。
- [ ] 材料衰减、表面粗糙度和曲率对检测的影响说明。
- [ ] 耦合剂类型、温度范围和耦合层厚度要求。
- [ ] 罐壁名义厚度及允许范围。
- [ ] 对应检测任务的标准试块或已知人工缺陷试块。
- [ ] 试块材质、尺寸、缺陷位置/尺寸和溯源证书。
- [ ] 每种典型壁厚、曲率和探头姿态下的原始标定数据。

### 7.4 空间外参标定

需要标定并提供：

```text
base_link -> ultrasound_probe_link
base_link -> phased_array_probe_link
```

其中探头坐标系必须以声学测量原点为依据，不能只使用外壳中心。

需要提供：

- [ ] 探头声学原点相对机器人安装法兰/基座的平移和旋转。
- [ ] 探头声束轴、阵元排列方向和扫描前进方向定义。
- [ ] 机器人 `base_link`、工具坐标系和罐体坐标系定义。
- [ ] 标定方法、标定工装、原始观测数据和优化残差。
- [ ] 平移、旋转的不确定度或重复性结果。
- [ ] 安装拆卸后是否需要重新标定及重标定判据。
- [ ] 可直接用于 ROS `/tf_static` 的 YAML/JSON 参数。

若探头有弹簧、浮动机构或姿态随接触力变化，还必须提供浮动行程/姿态传感器数据，或建立
接触状态下的动态探头位姿模型。仅标定固定安装外壳不能代表实际声学原点。

### 7.5 时间标定

需要提供：

- [ ] 超声/相控阵设备与 ROS 主机的共同时间事件采集数据。
- [ ] 设备时钟到 ROS 时间域的转换参数和方法。
- [ ] 固定 offset、长期 drift、短期 jitter 和统计区间。
- [ ] 软件触发、硬件触发、发射和首个采样点之间的延迟。
- [ ] 多 shot 法则周期内每个 shot 的时间偏移。
- [ ] PTP/PPS 锁定时间、失锁行为和重新锁定行为。
- [ ] 时间戳回绕、跳变和设备重启后的处理规则。
- [ ] 标定环境、持续时间、样本数量和原始数据。

不能只提供一个手工填写的固定时间偏移值。时间标定结果必须附带测量方法、残差和适用条件。

### 7.6 编码器和位置标定

- [ ] 编码器型号、分辨率、计数方向和回绕规则。
- [ ] 每脉冲对应的直线距离或角度。
- [ ] 编码器零点和机器人/罐体坐标零点的关系。
- [ ] 机械传动比、轮径、打滑和回程间隙补偿。
- [ ] 每个超声触发对应的 `trigger_id` 和 `encoder_count`。
- [ ] 编码器时间戳来源及与超声设备时钟的关系。
- [ ] 正向/反向重复扫查的位置重复性数据。

时间戳定位和编码器定位应相互校验。出现打滑时不能继续把时间积分位置标记为有效。

### 7.7 耦合和接触状态标定

- [ ] 接触力传感器零点、量程、线性和温漂。
- [ ] lift-off 测量方式、零点和有效范围。
- [ ] 耦合分数的计算方法及其输入信号。
- [ ] 有效耦合、弱耦合和脱耦阈值。
- [ ] 饱和、过载、离地和探头倾斜的判定条件。
- [ ] 不同表面状态、曲率和扫描速度下的阈值验证数据。

耦合质量未知时不得填入虚假的高分。无法确定有效性的帧应保留原始数据，但必须标记为无效。

## 8. 标定交付文件要求

每套标定至少交付：

```text
calibration_package/
├── calibration.yaml              # 机器可读的主索引
├── device_channel_calibration.*  # 通道幅值、延迟、坏阵元等
├── probe_geometry.*              # 探头/阵元几何
├── wedge_geometry.*              # 楔块几何和声学参数
├── focal_laws.*                  # 相控阵法则、延迟和加权
├── time_calibration.*            # offset/drift/jitter/触发延迟
├── extrinsics.yaml               # ROS 外参
├── encoder_calibration.*         # 编码器比例、方向和零点
├── reference_block.*             # 试块资料和证书
├── raw_data/                     # 标定原始数据
├── report.pdf                    # 方法、结果、残差和结论
└── checksums.sha256              # 文件完整性校验
```

机器可读主索引至少应包含：

```yaml
calibration_id: UT_PA_EXAMPLE_001
created_at: "YYYY-MM-DDTHH:MM:SS+08:00"
operator: "NAME_OR_ORG"
device:
  manufacturer: "VENDOR"
  model: "MODEL"
  serial: "SERIAL"
  firmware: "VERSION"
  sdk: "VERSION"
probe:
  model: "MODEL"
  serial: "SERIAL"
wedge:
  model: "MODEL"
  serial: "SERIAL"
time:
  source: "PTP/PPS/TRIGGER/DEVICE_CLOCK"
  stamp_reference: "FIRST_SAMPLE_OR_TRIGGER"
  offset_ns: 0
  drift_ppm: 0.0
  jitter_ns_rms: 0.0
extrinsics:
  parent_frame: "base_link"
  child_frame: "ultrasound_probe_link"
  file: "extrinsics.yaml"
validity:
  temperature_min_c: 0.0
  temperature_max_c: 0.0
  expires_at: "YYYY-MM-DD"
files:
  probe_geometry: "probe_geometry.csv"
  time_calibration: "time_calibration.json"
  report: "report.pdf"
```

所有数值必须注明单位、坐标系、方向和无效值表示。标定文件更新后必须生成新的
`calibration_id`，不得覆盖旧版本后继续使用相同 ID。

## 9. ROS 2 适配器需要完成的工作

设备适配器建议使用 `rclcpp/C++`，职责为：

1. 通过厂家 SDK 或协议读取原始数据。
2. 校验包长度、CRC、序列号、时间戳和状态位。
3. 将设备时间转换到项目 ROS 时间域，同时保留时间来源诊断。
4. 转换并发布标准原始 Topic。
5. 发布配置、设备状态、探头状态和 `/diagnostics`。
6. 统计接收帧、丢包、乱序、迟到、不完整帧、重连和缓冲区溢出。
7. 保证停止采集时能够完整释放 SDK 和设备资源。

适配器不得：

- 用主机当前时间覆盖有效的设备采样时间。
- 用零数组代替缺失数据并把消息标记为有效。
- 在回调线程中执行神经网络、成像或耗时融合。
- 在源码中写死 IP、设备序列号、聚焦法则或标定值。
- 静默丢弃不完整帧、未知配置帧或时间戳异常帧。

新设备接入后，还需要同步更新：

- 硬件 Launch 和参数 YAML。
- `record_topics.yaml`。
- `qos_overrides.yaml`。
- MCAP 验证器和结构检查。
- 时间同步器、故障注入和单元测试。

## 10. 建议增加通用锚点

当前同步器直接订阅 `UltrasoundFrame` 或 `EddyCurrentFrame` 作为锚点。相控阵原始帧很大，
且后续可能继续增加新的检测设备，建议新增轻量通用锚点：

```text
/inspection/anchor
```

建议至少包含：

- `header.stamp`。
- `sequence`。
- `trigger_id`。
- `source_topic`。
- `sensor_id`。
- `calibration_id`。
- `config_revision`。
- `valid` 和 `quality_flags`。

原始大帧与锚点通过序列号/触发 ID 关联。这样可以保留所有原始波形，同时独立控制融合索引
频率，避免大帧回调阻塞时间同步链路。

## 11. 验收流程

### 11.1 文档和接口验收

- [ ] SDK/协议、示例代码和版本说明完整。
- [ ] 原始数据类型、维度、布局、单位和缩放关系无歧义。
- [ ] 时间戳、触发、序列号和回绕规则无歧义。
- [ ] 所有配置均可查询，配置版本可追溯。
- [ ] 错误码、丢帧和状态位可被适配器读取。
- [ ] 标定包包含机器可读数据、原始数据、报告和哈希。

### 11.2 单设备验收

- 连续运行 60～120 秒，检查频率、时间戳、序列号和消息结构。
- 采集不少于三次静态已知目标数据，检查重复性。
- 验证数组长度与声明维度一致。
- 验证波形没有非预期截断、符号翻转或缩放错误。
- 断开并恢复设备，确认诊断、重连和无效状态正确。
- 检查配置修改后的首帧能够对应新的配置版本。
- 完成 MCAP 录制、正常关闭、结构验证和回放。

### 11.3 多设备动态验收

- 同时运行相机、雷达、IMU、机器人位姿和超声/相控阵 5～15 分钟。
- 使用共同事件验证时间偏移、漂移和抖动。
- 根据扫描速度验证时间误差对应的空间误差满足任务要求。
- 检查探头接触无效、机器人打滑或未吸附时融合结果正确失效。
- 检查缓存、RSS、CPU、网络和磁盘写入没有持续增长或阻塞。
- 检查所有丢包、不完整帧和队列溢出均有计数和诊断。

### 11.4 相控阵专项验收

- 所有阵元、法则和 shot 数量与配置一致。
- FMC/PWI/波束数据维度和排列可通过离线工具独立复现。
- 每个 shot 的时间和触发/编码器 ID 可追溯。
- 法则周期不完整时不会被标记为完整有效帧。
- 坏阵元、饱和和耦合异常能够正确进入质量标志。
- 原始数据可重新生成约定的 S 扫、厚度或缺陷结果。

## 12. 接口冻结前项目方需要确定的参数

以下参数需要由项目负责人、检测工艺和机器人团队共同确定，不能由适配器自行猜测：

- [ ] 最大和典型扫描速度。
- [ ] 允许的沿扫描方向和法向位置误差。
- [ ] 允许的跨设备时间误差。
- [ ] 检测对象材料、壁厚、曲率和温度范围。
- [ ] 使用纵波、横波或其他波型。
- [ ] 常规 UT、波束形成 PAUT、FMC 或 PWI 的实际需求。
- [ ] 是否必须保存全部原始阵元数据。
- [ ] 最大持续数据带宽和单次任务时长。
- [ ] 采用 PTP、PPS、硬件触发还是编码器触发。
- [ ] 探头接触力、耦合质量和 lift-off 的有效阈值。
- [ ] 需要实现的数据闭环还是检测驱动机器人复扫的控制闭环。
- [ ] 验收使用的标准试块、人工缺陷和判定指标。

上述参数确认后，才能冻结相控阵消息维度、缓存大小、QoS、录制带宽和时间验收阈值。

## 13. 对厂家的一页式交付清单

可将以下内容直接发送给设备厂家：

1. Linux C/C++ SDK 或完整协议、版本说明和示例程序。
2. 原始 A 扫/PAUT/FMC/PWI 数据，不接受仅截图或缺陷结果。
3. 数据类型、字节序、维度、布局、缩放、单位和无效值说明。
4. 硬件采样时间戳、帧/shot/触发序号及其单位和语义。
5. PTP、PPS、Trigger In/Out 和编码器能力说明。
6. 开始/停止、触发准备、配置设置与查询、设备状态和错误码接口。
7. 采样率、PRF、增益、延迟、滤波、闸门、TCG/DAC 和平均参数。
8. 相控阵阵元几何、发射/接收孔径、聚焦法则、延迟表和坏阵元信息。
9. 设备、采集卡、探头和楔块型号、序列号及固件/SDK版本。
10. 通道幅值/延迟、探头/楔块、声速、时间和空间外参标定文件。
11. 标准试块资料、标定原始数据、标定报告、机器可读文件和 SHA-256 哈希。
12. 正常、脱耦、饱和、丢帧、断连等离线样例及预期结果。

只有以上数据和标定资料齐全后，设备才能从“协议联调”进入“完整硬件验收”。
